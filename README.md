# MicRelay

同じiPhone / iPadのマイク音声を、接続したイヤホンやHDMI機器へリアルタイムに返すSwiftUIネイティブアプリ。iOS / iPadOS 18以降。iPhone Duoの開閉・回転時も利用可能な画面幅に追従します。

## 使い方

1. 有線・Bluetoothイヤホン、またはHDMI機器を接続します。
2. 「接続とマイクを更新」でマイクへのアクセスを許可します。
3. 本体マイク、またはiOSが利用可能として公開する外部マイクを選びます。
4. Bluetooth / USB / ライン出力の場合は、接続先がイヤホンであることを確認します。
5. 「モニターを開始」を押します。ゲインとシステム音量は別々に調整できます。

イヤホン・HDMI機器が未接続の場合は既定で音声を出しません。「モニターを開始」を押すと不足している条件を表示し、「本体スピーカーで開始」や接続先のイヤホン確認をその場で選べます。「本体スピーカーを使う」を明示的にONにする方法もあります。キャンセルでは音声を開始せず、スピーカー許可はアプリ起動時にOFFへ戻ります。メイン画面とEQ画面の開始ボタンは同じ操作です。モニターゲインのスライダー上限は設定画面で任意の正の数値に変更できます。初期の上限は200%で、アプリ独自の固定上限はありません。現在のゲインと上限は再起動・マイクや出力先の変更後も維持します。音声のフルスケールを超えた信号はクリップします。

「画面を閉じても続ける」は初期状態でONです。バックグラウンド音声と `mixWithOthers` を使い、ゲームや音楽と同時再生します。同じマイク・出力先のまま共有オーディオ設定が変更された場合は再構成し、OSが再開を許可した割り込み終了後も同じ接続なら再開します。イヤホンの切断や出力機器の変更では停止し、再開は手動です。他アプリがマイクを排他的に使用する場合などは、OSの制約により中断することがあります。

## 音質と設定

「イコライザー」で6バンドの周波数・増減・Qを調整できます。増減、ノッチ、ローカット、ハイカット、バンドストップ、バンドパスを選べます。バンドストップは指定範囲を減衰し、バンドパスは指定範囲だけを通します。追加した2種類は下限・上限の周波数を指定し、グラフの範囲表示を見ながら境界をドラッグできます。境界は約-3 dBの位置です。OFF時はIIRを完全にバイパスし、フィルター状態を読み進めません。ON時は同じRemoteIOコールバック内で処理し、先読みや再生バッファは追加しません。係数は約5 msで補間します。フィルター由来の位相・群遅延は周波数ごとに異なります。

「風切り音低減」は独立したON/OFFと60〜600 Hzの低域カット調整に対応します。初期値はOFF・120 Hzです。4次のハイパスで低域の風音を減らし、先読みや音声バッファを追加しません。値を上げると声の低音も減ります。広帯域の風音やマイクで既に歪んだ信号を完全に除去する機能ではありません。OSのマイクモードは変更しません。[フィルターと遅延の説明](docs/EQUALIZER.md)も参照してください。

イコライザー画面の「タップ音ゲート」は、立ち上がりを検出して短い時間だけ音を通します。初期OFF・12 ms、通す時間は1〜1,000 ms、最小入力レベルと背景音との差を調整できます。「検出に使う音」でEQ・風切り音低減の前／後を選択でき、どちらでも出力には有効なフィルターが適用されます。初期はフィルター後の検出です。開いている間も次の立ち上がりで時間を延長します。先読みや検出用の待ち時間は設けず、しきい値を超えたサンプルから通します。小さい立ち上がりは欠ける場合があり、他の急な音にも反応します。ゲートが開いている間の背景音も通るため、タップ音だけを識別・分離する機能ではありません。EQとは独立してON/OFFでき、OFFは検出・音量制御をバイパスします。

入力と風切り音低減・EQ・タップ音ゲート処理後（出力ゲイン前）の周波数スペクトラムを別キューの4096点Hann窓FFTで表示します。解析専用SPSCリングが満杯でも解析用データだけを捨て、音声出力は待ちません。画面を閉じる・バックグラウンドへ移ると解析表示を停止します。

音声モードは「自動／標準／測定／完全手動」から選択できます。初期設定の自動はモード・サンプルレート・バッファ候補を実際に動かし、入力・出力のOS報告値、実I/O、取得できたAudio Unit内部処理遅延を比較して、安定した組み合わせを選びます。「標準」「測定」ではモードを固定して残りを調整します。

「完全手動」ではフレーム数・サンプルレート・標準／測定をドロップダウンで選択します。無音で実際に動かし、要求と実値が一致し、入力が安定した場合だけ保存します。違う値が採用された場合や検証に失敗した場合は理由を表示し、前の設定と選択値に戻します。モニター中に変更した場合は前の設定で再開します。保存後も開始のたびに実値を確認し、使用中は要求値と実際の値を並べて表示します。完全手動ではバッファを自動調整しません。

「設定のバックアップと復元」からゲイン・上限・EQ・風切り音低減・タップ音ゲート・音声モード・手動I/O設定・背景継続・入力マイク・録画の音声除外設定をJSONへ書き出し、ファイルから復元できます。形式・版・数値範囲を全て検証してから適用します。新規書き出しは形式バージョン5で、旧バージョン1〜4のバックアップも読み込めます。旧形式にないタップ音ゲートはOFF、録画の音声除外はONで復元します。動画はバックアップに含みません。手動I/Oの適用確認は復元後の開始時に行います。スピーカー許可と接続先の確認は引き継がず、復元時はモニターを停止します。元のマイクが利用できない場合は本体マイクを選びます。

iPadなどの広い画面は標準SwiftUIのFormを2列で表示し、狭いウインドウは1列に切り替えます。外観はOSのライト／ダーク設定に従います。

日本語・英語に対応し、OSの優先言語とアプリ別言語設定に従います。画面・状態・エラー・読み上げ・マイク権限の説明をString Catalogで管理しています。[言語追加と翻訳の検証手順](docs/LOCALIZATION.md)では、翻訳用JSONの書き出し・取り込みも説明しています。

## 画面録画

iOS／iPadOS 27以降は「画面録画」から録画を開始できます。「録画からモニター音を除外」は初期ONで、イヤホンで聞くモニター音を動画から除きます。OFFでは動画にも含めます。録画前に選択し、録画中は変更できません。27未満は設定と開始ボタンをグレーアウトし、OS更新の案内を表示します。

設定項目の並びにある録画アイコン付き「画面録画」から開きます。OSの選択画面で画面全体を選ぶと、他アプリへ移っても録画を続けられます。録画用マイクとカメラはOFFです。停止すると写真ライブラリへの追加だけを許可する確認を表示し、許可済みなら自動で写真アプリへ保存します。写真の閲覧権限は要求しません。写真への保存成功を確認してからアプリ内のコピーを自動削除します。許可されない場合や保存に失敗した場合はアプリ内に動画を残し、「写真に保存」または「未保存の動画をまとめて写真に保存」で再試行できます。アプリ内に残っている動画の容量を表示し、未完了のファイルも含めて、確認後に手動削除できます。写真アプリの動画を削除する操作はありません。共有メニューからの書き出しも可能です。コントロールセンターから開始する録画には、この除外設定は適用されません。録画にはCPU・GPU・ストレージを使用するため、併用時の負荷や遅延は端末と画面内容に依存します。

実装は[ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-on-ios)の `excludesCurrentProcessAudio` と `SCRecordingOutput` を使います。録画はRemoteIOのコールバックを経由せず、録画の開始・停止でモニターのゲイン・EQ・音声セッション設定は変更しません。

## 低遅延の構成

- RemoteIO Audio Unitの出力コールバックから直接入力を取得し、そのコールバックで出力します。
- 通常の開始では現在の実レートで16・8・32・1フレームを標準／測定モードで交互に比較し、安定した候補があれば比較を約4秒で区切ります。余裕がある場合だけ追加レートを試します。安定しない場合は64〜2048フレームで回復を試みます。OSの呼び出し中と最後の採用確認は別に時間がかかるため、開始まで必ず4秒以内という意味ではありません。要求値とは別に実コールバック・実レート・処理量・欠落を検証します。
- 「レイテンシー → 詳しく最適化」は、44.1〜384 kHzのレート候補、1〜2048フレームと実レートで0.125〜20 msとなる候補を広く比較します。通常の開始時にこの全探索を行いません。詳細な比較中は音声が止まり、接続によって数十秒以上かかる場合があります。確認中は試行件数と経過秒を表示します。
- 選んだ候補を再適用して実値を再確認し、そのAudio Unitを再作成せずモニターへ移行します。検証済みの設定はアプリ再起動後にも使えるキャッシュへ保存します。同じ接続・入力・モード・OSでも毎回無音で実値と安定性を照合し、一致しなければ破棄して短い比較へ戻ります。キャッシュは最大16接続分で、ゲイン・EQ等の保存設定やバックアップとは別です。取得できない内部処理遅延は「—」で表示し、音響総遅延が0であるという意味には使いません。
- 起動時の猶予後、2秒の監視窓で3ブロック以上の入力欠落、または継続的な入力取得失敗を検出すると、バッファを段階的に広げます。30秒以上安定すると下限へ向けて半減を試し、失敗した再試行は間隔を最大300秒まで延ばします。端末モデル別の固定値はありません。
- 自動調整はバックグラウンドでも実行します。バッファ変更時はAudio Unitを再構成するため短いミュートが入ります。背景では音声セッションを維持します。詳しい探索中に背景へ移った場合は検証できた設定で継続を試み、前面へ戻ったときは短い比較で再確認します。詳しい探索は必要に応じて再度選択できます。前面では大きなバッファの継続に加え、自動モードで入出力のOS報告遅延が継続して増えた場合も再確認します。同じ大きなI/Oが続く場合の再試行間隔は最大300秒まで延長します。完全手動では自動変更せず、入力取得に継続して失敗した場合は停止します。
- セッションは `playAndRecord` + `mixWithOthers`。前面での開始・再探索時は、候補ごとにセッションを無効化して希望値を適用し、再び有効化して比較します。比較中は出力のみミュートし、保存ゲイン・EQ設定は変更しません。VoiceProcessingIO、録音ファイル、プレーヤー、追加のFIFOは使いません。
- リアルタイム処理は最適化したObjective-C++。コールバック内にSwift / Objective-C呼び出し、ロック、メモリ確保、ファイル書き込み、ログ出力はありません。
- 波形・メーターはロック不要のアトミック変数からUIが読み取ります。波形を描くために音声を待たせません。
- 開始直後などに入力が一時的に利用できないブロックは無音にして捨てます。古い入力を再生するための待ち行列は作りません。連続して失敗する場合は停止します。
- ルート変更・割り込みの通知を受けたスレッドで音声ゲートを閉じ、メインスレッドのUI更新より先にミュートします。OS側の切断時割り込みにもオプトインします。

表示されるI/Oバッファ時間は、マイクから耳までの総遅延を意味しません。入出力デバイス、AD/DA、OSの安全バッファ、Bluetoothの無線伝送・コーデック遅延が加わります。OS報告値も音響ループバックによる実測値ではありません。[KA13での比較記録とEQの遅延](docs/LATENCY.md)を参照してください。BluetoothマイクはHFPを使用し、入力を選ぶと出力側の通信方式・音質も変化する場合があります。高品質Bluetooth録音オプションは、遅延増加を避けるため使用しません。

Bluetooth・USB機器のイヤホン/スピーカー種別を完全には判定できないため、接続ごとの確認が必要です。HDMIは追加確認なしでモニター出力先として許可します。AirPlay、CarPlay、受話口はモニター出力先として許可しません。Bluetoothの組み合わせによっては希望する入力・出力をOSが同時に選べない場合があり、その場合は別のマイクに勝手に変更せず停止します。

## ビルド

`MicRelay.xcodeproj` をXcodeで開き、署名チームと実機を選んで実行します。外部ライブラリは不要です。

```sh
# プロジェクトの再生成が必要な場合のみ（Homebrewのxcodegen）
xcodegen generate

xcodebuild -project MicRelay.xcodeproj -scheme MicRelay \
  -configuration Debug -destination 'generic/platform=iOS' \
  -derivedDataPath build -allowProvisioningUpdates build
```

`project.yml` がプロジェクト設定の元です。Bundle IDは所有ドメイン `ryuya-dev.net` の逆順による `net.ryuya-dev.MicRelay` です。iOS 26以降のアイコンは `MicRelay/Resources/AppIcon.icon` の2層構成で、Liquid Glass・ダーク・Clear・Tintedに対応します。AppleのIcon Composerレンダラーによる [6種類のプレビュー](store/icon-previews/appearances.png) があります。`scripts/export-icon-previews.sh` で再生成できます。旧OS向けの不透明アイコンは `swift scripts/generate-icon.swift` で生成します。

## 動作診断

「レイテンシー → 動作診断」に処理フレーム数、実際の入力/出力ピーク、音声エラー、一時的に欠落したブロック数、バックグラウンド中に処理したフレーム数と時間を表示します。入力波形は実マイクの信号です。小さい音を見やすくするため描画のみ固定倍率で拡大しています。

Debugビルドは停止時・バックグラウンド復帰時にアプリ内 `Documents/diagnostics.json` に数値診断を保存します。音声・波形サンプルは保存しません。検証結果と残る確認項目は [docs/VALIDATION.md](docs/VALIDATION.md) を参照してください。

実マイクの検証中はDevice Hubの実機画面接続を終了してください。Appleの仕様により、実機をDevice Hubで操作している間はマイクを利用できず、入力が無音になることがあります（[Appleの説明](https://developer.apple.com/documentation/xcode/interacting-with-your-app-in-device-hub#Handle-camera-and-microphone-access-conflicts-on-physical-devices)）。画面操作の検証と実音の検証を分け、実音は画面接続を終了してから端末操作と数値診断で確認します。フレーム数が増え、音声エラーが0でも、実マイクの入力や聞こえる音を確認したことにはなりません。
