# ビルド8の負荷・メモリ削減

音声の計算結果を変えずに、周波数解析と表示へのデータ転送を軽くした変更。録音・先読み・再生バッファの追加はない。

## 変更

- FFTの周波数表128点と各点の解析区間を、実サンプルレートが変わったときだけ計算する。入力と処理後で同じ表を使う。
- 循環した解析データにHann窓を直接掛ける。毎フレーム生成していた4096 Floatの並べ替え配列2本（計32 KiB）が不要になる。20回/秒では640 KiB/秒分の一時配列生成と要素コピーを除去する。
- 解析用の4配列は初回開始時に確保して再利用し、FFT本体も実際に必要になるまで作らない。起動時の約120 KiB分の配列とFFTセットアップの先行確保を避ける。アプリ全体のRSS削減量を実測した値ではない。
- 波形128点をFloatのままSwiftへ渡す。NSArray・NSNumberを経由した変換をなくす。10回/秒なら1280個/秒の数値ボックス化・取り出しが不要。SwiftUIに渡す値は引き続き独立した配列スナップショットとする。
- 解析専用リングの読み取りを、折り返し位置で分けた最大2区間の連続コピーにする。公開位置のacquire/release、容量超過時の解析だけの破棄、再生が解析を待たない性質は維持する。
- 手動設定の通常の候補リストは静的配列を共有する。毎回Setを作って並べ替えない。バックアップから復元した標準外の値は候補に残す。

RemoteIOのrender関数、EQ・風切り音低減のフィルター、ゲイン計算、I/Oの自動選択・手動検証は変更していない。render関数はビルド7のソースと完全一致することも確認した。

## 再現できる補助測定

MacとXcodeが必要。マイク、音声セッション、実機にはアクセスしない。

```sh
python3 scripts/benchmark_spectrum.py --baseline a6ef5e0 --output artifacts/spectrum-benchmark.json
```

Apple M5 Max、Swiftの最適化あり（`-O -whole-module-optimization`）で、48 kHzの入力・処理後の4096点FFTを1組として比較した。32回のウォームアップ後、1000組を7試行。単一プロセスで旧版・新版の実行順を交互にした結果の中央値は以下。

|処理|解析1組あたり|
|---|---:|
|ビルド7|51.31 µs|
|ビルド8|45.39 µs|

この試行では約11.5%短縮し、結果のチェックサムは一致した。これはMac上の周波数解析処理だけの値で、アプリ全体のCPU削減率、iPhone/iPadでの処理時間、音響総遅延の短縮率ではない。起動メモリの確保延期、波形転送、ネイティブリングのコピー改善はこの時間に含めていない。CPUや実行条件によって結果は変わる。

## 検証範囲

旧版のFFTをテスト用に固定し、循環位置と8〜384 kHzの実レート変更に対する周波数表・全128点のdB値・ピーク周波数の一致を確認する。保持中のフレームがキャッシュの更新で変わらないこと、最初の解析が最新4096点になることも確認する。

ネイティブのコピーは、折り返し、0件・容量上限、読み取り位置のUInt32オーバーフロー、NaNのビット列・負のゼロ、出力先の前後の境界を検証する。テスト入力は単体テスト専用で、アプリやUIテストの波形へ合成信号を差し込む処理はない。

実機の起動・音声確認を後回しにする指示は継続する。実機上の音響遅延は再計測しない。前回の更新依頼に合わせ、iPadは保存設定を保持してビルド8へ上書き更新した。iPhone 17は接続できず更新を保留。どちらも起動・音声確認は行わず、審査・配布設定は変更していない。
